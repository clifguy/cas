# Codex runtime for the existing development workflows

Read this reference before executing the skill. It defines shared runtime mechanics; the skill body supplies workflow policy. Current system/developer instructions and the user's scope take precedence. This inactive candidate requires explicit project binding; its presence does not activate the proposed profile.

- Resolve skills from the current catalog and read their actual `SKILL.md` and referenced resources. A slash command names a workflow, not a callable tool. For missing repository skills, inspect `.agents/skills` from the target worktree through its ancestors and the configured Codex skill locations. Do not invent `.Codex` directories, translate Claude paths mechanically, or silently substitute an unrelated skill. Missing required dependencies block the affected step; optional dependencies remain optional.
- Respect the host's actual collaboration mode. Write a concrete plan in the current conversation; there are no assumed enter/exit-plan tools. Reuse existing authorization for the same scope. Do not skip required analysis when approval is already supplied. Read-only work and reversible preparation can proceed while a new caller decision is pending. Publication of PR comments must be explicitly authorized by the user or the approved parent workflow; a request only for private review does not authorize posting.
- Use current execution tools. Anchor every command to a verified absolute worktree via `workdir` or `git -C`. Shell variables and cwd do not carry across invocations. `git worktree list` is repository-scoped, not global: run it against a known checkout, parse full porcelain records, and verify the selected repository/branch/path. Resolve the actual forge repository, remote and base branch; do not infer them from an arbitrary sibling worktree. Preserve dirty, untracked, ignored and unrelated staged work.
- Long commands may return a session id. Poll it with the available execution-session tool and await a terminal result. A running command is not success; ending the assistant turn does not establish an automatic wakeup. Keep individual waits at most 60 seconds and give concise progress updates without printing every poll. Use the function-cell wait only for its own running cell id.
- Resolve the selected SAGE capability from the compatible shared project-policy bundle for every SAGE operation; follow its explicit external or compatibility route. Inspect the served tool contract and target vault's live configuration. Names, field shapes, URIs, pagination and commands in the workflow are examples to validate, not substitutes for that contract. Retrieve current project-owned steering policy before applying a gate; preserve its authority and report conflicts or unavailable policy. Never mutate vault storage directly except a specifically authorized test-fixture exception within its exact bounds.
- Paginate all populations used for an exhaustive claim, including PR comments/checks, catalog rows and edges. A failed, truncated, forbidden or malformed lookup is unknown, not zero, absent, green or waived. Resolve version chains through supported chain semantics; document ids are opaque, lifecycle alone does not identify a head, and unrelated chains sharing a ticket id are collisions. Read edge validity/retraction state before treating an edge as a live dependency.
- Use structured arguments or safely quoted local files for multiline text and shell data; use `--body-file` for PR comments/descriptions. Keep secrets and transferred bytes out of tool output. Read back external writes and retain item-level receipts. After an ambiguous write, reconcile before retrying; never duplicate a comment, ticket or transfer by blindly retrying.
- Never edit permission settings to work around a denial. Use the host's actual escalation flow when necessary, preserve the supplied authorization, and report any remaining automatic-review rejection with its stated reason. Do not claim an inherited Claude permission rule is a Codex grant.

## Cross-skill review handoff

`converge-review` coordinates; `review-pr` independently inspects; `disposition` belongs to the authoring context; `merge` checks the resulting protocol. Carry repository/PR identity, exact base and head SHAs, global pass number, cycle identifier and ordinal, correlation token, and the approved policy/decision boundary across each handoff. Refresh revisions before reuse or publication. Duplicate, missing, stale or contradictory evidence cannot satisfy a gate. Global pass number and cycle ordinal are different.

Independent review means no authoring conversation history. A matching model or shared worktree does not imply self-review. A declaration/token alone does not prove independence. When delegation is requested by the executing workflow, use the current subagent API with `fork_turns="none"`; verify requested and exposed settings distinctly. Apply converge-review's same-model/higher-effort contract for its review dispatches; never infer model/effort or use a copied model nickname. A reviewer does not fan out again unless expressly requested. Historical release notes are archival evidence, not current gates.
