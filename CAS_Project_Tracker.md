- CAS-ADR-019 added 2026-04-29, status proposed: Auto edge inference may delete its own prior edges to repair chains; hand-curated edges are protected by a provenance gate. - CAS-ADR-020 added 2026-05-01, accepted 2026-05-01: Abstract generation prompt — descriptive framing for agent relevance triage. Refines the prompt design for semantic abstract generation given the abstract's purpose (an agent that has discovered a document via MCP search reads the abstract to decide whether to fetch the full document) and the existing greedy-decoding determinism property tested by TEST-SAGE-AD-029. The original prompt ('You are a technical abstraction engine ... key concepts, methods, and findings') was research-paper-shaped and document-type-blind; an empirical investigation of seven editorial-guideline documents in the theology vault documented four reproducible failure modes: (1) genre-instantiation (a guideline about pastoral letters became a sample pastoral letter), (2) hypothetical-paper composition (a guideline about academic theology became the abstract of an invented paper on divine silence), (3) fabricated specifics (a guideline about executive communications produced an abstract containing an invented $120,000 budget reallocation with fabricated percentages and dates — factual-safety failure), (4) framing-tax openings (the master Editorial Guidelines opened with three sentences of generic AI-discourse boilerplate before reaching content). Five options weighed: status quo (rejected: pathology is reproducible), sampling instead of greedy (rejected: masks rather than fixes, breaks AD-029), per-doc-type prompt overrides (rejected: heavier than needed), two-pass self-critique (rejected: violates planning-then-execution-separation principle), descriptive third-person prompt with doc_type and anti-fabrication clauses (chosen). Decision: the system prompt frames the task as producing a relevance-triage card for a discovering agent; requires descriptive third-person voice ('This document...', 'The guideline...'); receives doc_type as a parameterized input; forbids writing in the genre the document discusses; forbids introducing specifics (numbers, names, dates, quotes, examples) not present in the source; instructs against restating metadata (title, doc_type, tags, project) the agent already sees; preserves density-proportional length from CAS-ADR-011. Greedy decoding (TEST-SAGE-AD-029) preserved unchanged; rationale relies on it (deterministic systems require prompts that close all expected attractors at design time). Empirical validation: in-process A/B reabstraction of the seven editorial-guideline documents eliminated all four prior failure modes; Social Media control remained clean. Theology vault rows backfilled with new abstracts. Stored abstracts under the old prompt are not automatically migrated; re-abstraction is operational, per-vault, on demand. Downstream impacts: SAGE Architecture Reference (abstraction stage description — refresh on next revision); CAS-ADR-011 (companion ADR; ADR-020 does not supersede it). - CAS-ADR-021 added 2026-05-01, status proposed: Metadata inference and review are caller responsibilities; SAGE accepts authoritative values. Resolves two related symptoms that trace to a single boundary leak: (1) ChecklistTemplate v3.2 ingest produced doc_type=reference_document on a chain whose predecessor was steering_template, requiring manual sage_update_metadata correction — the SAGE ingest pipeline never consults the predecessor's doc_type even when supersedes_document_id is supplied; (2) routine agent ingests via the SAGE MCP toolset are appearing in the CAS application's bulk-ingest review queue because vault config metadata_extraction.review_required=true causes SAGE to mark every ingested document metadata_confirmed=false regardless of caller. Both trace to filename inference and review-queue management running inside SAGE on behalf of agent callers who already have authoritative metadata — a violation of principle 4 (SAGE indexes everything and owns nothing) and principle 5 (boundary rule). Four options weighed: status quo with chain inheritance only (rejected: leaves boundary leak), per-vault default-to-review with caller override (rejected: wrong granularity — the same vault legitimately sees both authoritative and uncertain ingests), hard reject on doc_type divergence (rejected: treats inference as authoritative when the underlying problem is that inference shouldn't run for authoritative callers), caller-responsibility model with chain-inheritance exception (chosen). Decision: IngestRequest gains needs_review: bool with default false. When false, SAGE commits caller values as-is and skips filename inference and the metadata_confirmed=false setter. When true, SAGE marks metadata_confirmed=false and may invoke filename inference for fields the caller omitted. FilenameParser is preserved as a SAGE-provided library exposed via a new POST /parse-filename endpoint and corresponding MCP tool — callers (notably the CAS app's bulk ingest workflow) invoke it before commit if they want filename-based suggestions. One exception is retained inside SAGE's ingest pipeline: when supersedes_document_id is present, the predecessor's doc_type, project, and authority_scope are read; for each of these three type-shaped fields, if the caller did not supply a value, the predecessor's value is applied. Caller-supplied values continue to win on a per-field basis. Version-specific fields (title, version_label, document_date) are excluded as definitionally different across versions; tags is excluded because set semantics make 'inherit' ambiguous (union, replace, skip). Mirrors ADR-019's trust direction for edges: SAGE corrects its own prior conclusions but defers to caller authority. The vault config option metadata_extraction.review_required is deprecated; it is removed once the CAS app is updated to pass needs_review=true explicitly on bulk-ingest calls. Schema version unchanged. Downstream impacts: docs/fs/sage/ IngestRequest schema (add needs_review, manifest version bump), sage/models/schemas.py Pydantic regen (principle 8), sage/services/ingestion.py (gate inference and metadata_confirmed=false on needs_review; add chain inheritance for the trio), new /parse-filename endpoint and MCP tool, sage_ingest tool docstring update, one-time pending_metadata queue triage per vault (count + bulk-confirm or hand-walk before flipping the default), CAS app bulk ingest workflow (call parse_filename → suggest → human confirm → call sage_ingest with confirmed metadata). All CAS documentation is currently stale and will be updated as part of post-beta consolidation; ADR is the authoritative record until then.

## Open Considerations

- **Generator/evaluator separation pattern.** GAN-inspired multi-agent pattern using separated generator and evaluator agents for artifact quality gates. Externally validated by Anthropic Labs (Rajasekaran, Mar 2026) and LangChain (Trivedy, Mar 2026). Evaluator agents tuned for skepticism outperform generator self-assessment on finished work products. Evaluate for PIM Health domain during ROOT Harness implementation.
- **Sprint contract pattern for orchestrator plans.** Orchestrator plans must include explicit, negotiated success criteria before execution begins. Derived from Anthropic Labs harness work where generator and evaluator negotiated a "sprint contract" defining testable completion criteria before implementation. Mechanism: the workflow schema's state_schema (docs/fs/root_harness/workflow.schema.json) defines required fields per workflow, including success criteria. Specific plan-shape constraints are domain configuration, defined per workflow in each domain instantiation. ROOT Harness enforces the requirement by refusing to execute workflows whose initial state does not satisfy the state_schema.
- **Context reset over compaction as default pattern.** Empirical evidence (Anthropic Labs) that context resets with structured handoff artifacts outperform in-context compaction for long-running agent work. LangGraph checkpoint-and-resume already supports this pattern. Orchestrators should be designed for clean handoffs through SAGE-mediated state, not in-context summarization.

## Flagged for Discussion

- **version_chain inference tightened to require matching doc_type (2026-04-25).** `_version_chain` in [app/backend/edge_inference.py](app/backend/edge_inference.py) now groups by `(title, project, doc_type)` rather than `(title, project)`. Two documents that share a title and project but resolve to different doc_types no longer chain. Items with null doc_type group only with other null-doc_type items (conservative default). Schema description in [docs/fs/sage/edge_inference.schema.json](docs/fs/sage/edge_inference.schema.json) updated accordingly. Test spec: TEST-APP-EI-015 wording revised; TEST-APP-EI-015b added. Worth reviewing whether a paired refinement to filename_code_match is warranted (currently it pairs workflow→content based on shared codes only, with no doc_type stability constraint beyond the workflow/content split).
- **Supersedes edge chain specification (architecture correction).** The SAGE Architecture Reference does not specify whether supersedes edges form a linear chain (v7→v6→v5) or an exhaustive graph (v7→v6, v7→v5, v7→v4, ...). Design decision 2026-04-08: linear chain only. Each version supersedes its immediate actual predecessor. The architecture reference should be corrected to state this explicitly.
- **filename_co_location deferred to Phase 2.** The bundles_with inference method via filename_co_location is deferred until a ZIP adapter is available. The primary use case (patent draft bundled with its figure package) requires ZIP support. Flag for inclusion when ZIP adapter is implemented.
- **Self-evaluation scope.** Steward self-review of plans and checklists appears sound (validated by Clif's experience across hundreds of PIM sessions). Independent evaluation may be needed for finished artifacts, where the producing agent has accumulated context-level commitment to its own decisions. The failure mode is strongest when evaluating effort-intensive completed work, not lightweight pre-execution plans. Needs further analysis to determine where CAS draws the line.
- **Formal Substrate as plan-shape authority (partially resolved).** The Formal Substrate defines the mechanism for valid plan shape: the workflow schema's state_schema section specifies required fields, types, and constraints for each workflow's state dictionary. ROOT Harness enforces plan validity at execution time by validating initial state against the state_schema before dispatching. The separation-of-concerns pattern holds: Formal Substrate says "plans must have this shape," ROOT Harness says "I won't run plans that don't have this shape." Remaining: the specific plan-shape constraints (which fields constitute a valid plan, what success criteria look like) are defined per domain instantiation. PIM Health will be the first test of whether the mechanism is expressive enough.
